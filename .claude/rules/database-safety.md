# 数据库与修复脚本安全规则

- 禁止直接修改生产数据库或把 E2E 数据写入正式历史、供应商主数据。
- 任何批量修复先备份、dry-run、输出逐行守恒报告，再由用户确认写入。
- 修复脚本必须显式接收目标项目、submission 或批次，禁止写死供应商、项目、页码和本机临时路径。
- 数据迁移必须有前后计数、金额、外键和唯一性校验；失败时事务回滚。
- 不得用 `create_all` 或 SQLite 临时重建替代长期迁移方案。新增持久化字段应提供版本化迁移。
- 脚本默认只读；写模式使用明确参数，并记录操作者、时间、输入文件哈希和输出摘要。
- 不删除、不重建用户数据，除非用户明确授权且已验证备份。
