## 0. 一句话

系统当前只认「含税/不含税」一个口径维度，而真实招标里决定"能不能比"的还有
**交付范围、原材料价格基准、付款条件、行级技术口径**四项。它们的原文**已经存在
库里**（`remark` 字段两侧都有、都能解析），但**矩阵与评标代码里对 `remark` 的
引用次数是 0**——口径事实躺在一个没人读的字段里。

本设计不做折算，只做**识别 → 标记 → 拦截 → 由人裁定**。

## 1. 真实材料给出的四类口径

### 1.1 交付范围（份级，母线槽）

母线第一轮开标汇总表备注列：

| 投标单位 | 含税总价 | 备注 |
|---|---|---|
| 上海都安实业 | **827,034** | **不含安装** |
| 江苏永旗电气 | 892,448 | 含安装 |
| 上海塞克西德 | 924,889 | 含安装 |
| 大航有能电气 | 867,207 | 含安装 |

按最低价排，都安第一——**它便宜只是因为没含安装**。二轮都安改为含安装，
827,034 → 1,024,072（+197k），这不是涨价，是范围变了。

> 这正是"静默混比"最典型的一次：四个数字在同一列里，谁都看不出其中一个不是
> 同一件事。系统今天会把它们一起排序。

### 1.2 原材料价格基准（份级，母线槽）

一轮四家各报各的铜价基准：77,540 / 76,600 / 77,470 / 77,680 元/吨；
**二轮全部统一到 73,410**。二轮的意义就是把基准拉平后重报。

⇒ 跨轮比较"降了多少"，在铜价基准变了的情况下**没有意义**。

### 1.3 付款条件（份级，潜水泵）

潜水泵二轮三家**全部涨价**：凯泉 371,766→394,498、东方 383,949→420,078、
俊能 355,880→360,260。同时俊能把付款条件从"货到现场二个月后付 70%…"改成
"一个月付至 95%（其中 50% 商票）+ 银行质量保函付至 100%"。

涨 4,380 换回款大幅提前——纯价格排序会判成"变贵了"。

### 1.4 行级技术口径（行级，母线槽报价清单）

`临港中科院-母线报价清单.xlsx` 的**备注列**：

| 名称 | 规格型号 | 单价 | 备注 |
|---|---|---|---|
| 密集母线槽 | 密集母线槽 LS-630A/5 | 927 | **4*45** |
| 密集母线槽 | 密集母线槽 LS-800A/5 | 1107 | **4*55** |
| 母线插接箱 | 125A | 1600 | **XT2N160 TMA125 F** |
| 始端箱 | 630A | 447 | **空箱** |

- `4*45` / `4*55` = 导体规格，**直接决定含铜量**——1.2 的铜价基准要落到行上才有意义
- `XT2N160 TMA125 F` = 插接箱内断路器型号
- **`空箱`** = 始端箱不含断路器 → **行级范围差异**

⇒ 只看 名称+规格型号，"始端箱 630A"两家看着一样，一家 447 元一家可能上千——
差别整个写在备注里。**对齐匹配现在不读备注，会把它们判成同一行去比价。**

## 3. 设计

### D1. 口径是**多维**的，不能塞进现有的单值 `price_basis`

`price_basis` 保持不动（税口径，行级）。新增并列维度，按**粒度**分两层：

**份级（submission-level）** — 整份报价的商务口径，写在封面/汇总表备注：
- `delivery_scope` 交付范围：含安装 / 不含安装 / 含运费到场 / …
- `commodity_benchmark` 原材料基准：`{material: "铜", price: 73410, unit: "元/吨"}`
- `payment_terms` 付款条件：结构化槽位（首付比例/账期/质保金比例/质保年限/票据类型）

**行级（line-level）** — 写在报价行备注：
- `line_scope` 行级范围：如「空箱」（不含断路器）
- `line_tech_spec` 行级技术口径：如导体规格 `4*45`、断路器型号 `XT2N160`

> 为什么必须分两层：付款条件永远是整份的，导体规格永远是行的。混成一层，
> 要么份级字段在每行重复（改一处漏一处），要么行级差异被份级平均掉。

### D2. **只识别与拦截，绝不折算**

不做：不把「不含安装」加上一个估算安装费；不按铜价基准换算总价；不给付款条件
做资金成本折现。理由与 `price_basis.py` 里那句"绝不 ×1.13 / ÷数量自行推导"同源
——折算需要投标方没给的数（安装单价、含铜量占比、公司资金成本率），凭空造出来
的可比性比不可比更危险。

差异只被**呈现**，由评标小组裁定。

### D3. 门禁：复用既有三态，差异 → **未决**，不静默纳入也不静默排除

沿用 `basis_unconfirmed` 的范式，扩成带维度的：

```
cell/submission.eval_status = "basis_unconfirmed"
basis_conflicts = [
  {dim: "delivery_scope", values: {"都安":"不含安装","永旗":"含安装", ...}},
  {dim: "commodity_benchmark", values: {...}},
]
```

规则：

1. **轮内横向**：同一轮参评的各份在任一维度取值不一致 → 该轮**不出总价排名**，
   出「口径不一致，不可直接比较」阻断卡，逐维列出差异。
2. **跨轮纵向**：同一供应商相邻两轮在任一维度取值不一致 →
   `round_trend.not_comparable_reason` 增加对应原因码（该机制已存在，扩枚举即可，
   不新建第二套）。
3. **行级**：锚点行与报价行的 `line_scope` / `line_tech_spec` 冲突 →
   该单元格 `pending`，不进评标总价（与现有 pending 语义一致）。
4. **显式接受**：用户可声明"已知差异并接受"，记录 who/when/why
   （照抄 `AnchorMissingAck` 的先例：不改数值、不改单元格状态、留审计）。
   接受后排名可出，但结论上**永久带口径差异标记**，导出同样带。

### D4. 口径值怎么来：LLM 抽取候选 → 人确认 → 确定性判定

分工严格照 CLAUDE.md：**LLM 只做识别与归一，不做裁定**。

```
备注原文（自由文本）
   ↓ LLM 结构化抽取（份级+行级）
候选值 status=ocr_candidate，永远带原文与来源(page/row)
   ↓ 用户在校对界面确认/修正
确定值 status=confirmed
   ↓ 纯等值比较（无模型调用）
口径一致？→ 出排名 ／ 不一致 → 阻断卡
```

三条硬约束：
- **门禁只吃 confirmed 值**。LLM 抽到但没人确认 → 触发 REVIEW，不触发拦截结论，
  也**不当作"一致"放过**（未知 ≠ 一致）。
- 抽取结果必须带**原文与来源**，界面上一律"原文可见"，不给只显示归一值的视图。
- 归一表（如「不含安装/不含安装费/安装另计」→ 同一值）是**可审计的词表**，
  不是模型即兴判断；词表变更要有记录。

### D5. 每轮概述里的 LLM 分析（用户 2026-09-03 提出）

在轮次卡里加一段 **本轮口径与商务条款说明**，由 LLM 生成，约束：

- 只说**已在库中的事实**：谁的备注写了什么、哪两家在哪个维度不同、
  同一供应商跨轮哪个维度变了。
- **必须逐条引用证据**（供应商 + 原文 + 页码/行号），不能出现没有出处的句子。
- **不得**给出：谁更优、谁应中标、折算后谁更便宜、任何名次或推荐。
- 结论性数字（总价、区间、名次）一律来自确定性服务，LLM 不参与计算，
  只在旁边解释"为什么这些数字这一轮不能直接比"。
- 生成失败/超时 → 该段缺省，**不阻塞**轮次卡其余内容。

示例（母线一轮）：
> 本轮四家在**交付范围**上不一致：上海都安备注「不含安装」，其余三家「含安装」。
> 四家的**铜价基准**各不相同（77,540 / 76,600 / 77,470 / 77,680 元/吨）。
> 因此本轮总价不具备直接可比性。（证据：开标汇总记录 备注列，第 1 页）

### D6. 对三个核心目标的影响（用户 2026-09-03 明确的核心目标）

| 核心目标 | 口径维度带来的要求 |
|---|---|
| **各供应商每轮报价对比** | 轮内任一维度不一致 → 不出排名，先给差异卡（D3.1） |
| **与历史价格横向对比** | 历史价格**必须连口径一起入库**。`Quote.remark` 已有，但没有结构化口径字段——一条「密集母线槽 927 元/米」脱离 `4*45` 与当时铜价基准就是废数据，拿去比只会得出错误结论。**建议：历史价入库时同步冻结口径快照，缺口径的历史价在比对界面标为"口径不明，仅供参考"。** |
| **逐轮报价趋势** | 趋势必须按维度分段：基准/范围变了的两轮之间不画降幅线，只标"口径变更"。`round_trend.py` 的 `not_comparable_reason` 是现成挂点 |

### D7. 回答"报价清单是不是还得带着备注"

**必须带，而且它不是附注，是可比性的一部分。** 三个理由，全部有实据：

1. **备注里装着规格列装不下的关键差异**：`4*45` / `4*55`（导体规格→含铜量）、
   `XT2N160 TMA125 F`（箱内断路器）、`空箱`（不含断路器）。
2. **不带备注，对齐会把不同的东西判成同一行**：「始端箱 630A」两家名称规格全同，
   一家是空箱——现在的匹配只看 名称/规格/canonical，**不读备注**，会直接对上去比价。
3. **招标清单的备注是"要求"，报价清单的备注是"承诺/偏离"**，两者语义不同、
   不可当同一字段比对，但正是**两者之差**构成响应性判断的依据。

⚠ 同时要说清：本次材料里最要命的口径（不含安装、铜价基准）**不在报价清单行备注里，
而在开标汇总表的份级备注里**。所以"带上行级备注"是必要条件，不是充分条件——
份级商务口径需要 D1 的独立落点。

## 4. 分期

| 期 | 内容 | 是否动后端 |
|---|---|---|
| **P0** | 轮次卡去掉"明细合计区间"这种邀请比较的形式；同轮有备注差异时显示「口径可能不一致，见备注」并把原文摆出来 | 否（纯前端，读现有 remark） |
| **P1** | 份级 `commercial_terms` JSON 落点 + 校对界面手工录入/确认（先不上 LLM）；轮内一致性判定 + 阻断卡 | 是 |
| **P2** | LLM 从备注抽结构化候选（ocr_candidate）；每轮概述说明段（D5） | 是 |
| **P3** | 行级 `line_scope`/`line_tech_spec` 进对齐匹配；`round_trend` 原因码扩展；历史价口径快照 | 是 |

P0 可以立刻做且零风险——**在系统能读懂备注之前，先别再帮用户做错误的聚合**。

## 5. 决策（用户 2026-09-03 确认）

### 决策 1：按 P0 → P3 整体排期

四期全部排进计划，不只做 P0。P0 先落地（零风险、纯前端），其余按序推进。

### 决策 2：份级口径**直接上 LLM 抽取**，不走"先纯人工"的过渡

⇒ **P1 与 P2 合并**：校对界面一上来就展示 LLM 抽出的结构化候选，用户确认/修正。

我原本建议先纯人工（先把门禁跑通再让模型喂它），用户选择直接上模型。据此
把风险控制加厚，D4 的三条硬约束**一条都不能松**，并补两条：

- **门禁只吃 confirmed 值这条变得更关键**：模型抽错时，错误值不会自己变成
  拦截依据；未确认一律触发 REVIEW，而"未知 ≠ 一致"。
- **必须能分辨"模型没抽到"和"原文里确实没有"**：前者是抽取失败（要重试/人工补），
  后者是投标方没声明（是业务事实，本身就是疑点）。两者混成一个空值，
  就永远查不出模型漏抽了多少。落地为三态：`extracted` / `not_present` /
  `extraction_failed`，不用 null 兜底。

### 决策 3：「接受口径差异」**不限制角色**，只留审计

⇒ 任何角色都可以声明接受，从而让该轮出排名。据此把补偿措施做实（否则这就是
一个人人可开的旁路）：

- 记录 who / when / why（why 必填，不给"确认"一键放行）
- 结论**与导出**上永久带口径差异标记，不可关闭
- 声明本身显示在轮次卡上，**对所有人可见**——不藏进详情或日志里
- 进操作日志，可追溯可回滚

### 决策 4：历史价格库的无口径老记录 → **保留 + 标"口径不明"**

仍参与横向对比，但界面明标"口径不明，仅供参考"，且**不进任何确定性结论**。
新入库的历史价必须带口径快照（P3）。
