# 比价流程 v2.3 重构设计

**背景**：v2.2 存在三个结构性问题（来自 ChatGPT 代码审计）：
1. 低置信锚点直接写成 `confirmed`，绕过人工复核门禁直接进矩阵
2. 同一供应商对同一采购项多行报价时互相覆盖（`bid_matrix.py` 直接赋值）
3. 流程顺序不符合采购员实际操作习惯（先配置 → 再上传，而非先上传 → 再确认）

---

## 一、新用户流程

```
Step 1  上传采购清单
        └─ 上传 .xlsx → 解析预览（品名/规格/数量列表）
        └─ 自动识别品类，可编辑
        └─ 确认后进入 Step 2

Step 2  上传供应商报价
        └─ 多文件拖入，OCR 识别 + 供应商确认
        └─ 所有文件入库后，进入 Step 3

Step 3  对齐核查（门禁）← 核心变更
        ├─ 系统自动运行嵌入匹配
        ├─ 高置信（≥0.70）→ status=confirmed，列表展示
        ├─ 低置信（<0.70）→ status=pending，必须逐条操作
        │   操作：「确认归入」或「移除」
        │   说明文字："系统将[供应商报价X]归入[采购项Y]，
        │              相似度 63%，请确认是否合理"
        └─ 清单外报价：展示说明，不参与矩阵
        
        [pending 项全部处理完 → 才可点"生成比价矩阵"]

Step 4  比价矩阵
        └─ 只消费 status=confirmed 的组
```

## 二、后端变更

### 2.1 anchor_match.py — 低置信改为 pending

```python
# 旧
status = "confirmed"

# 新
status = "confirmed" if min_cos >= LOW_CONF else "pending"
```

`/analysis/anchor-review` 返回结构不变，`low_conf_groups` 对应 `pending` 组。

### 2.2 新增接口 POST /analysis/tender-list/preview

只解析 xlsx，不跑嵌入，立即返回预览数据。

```json
{
  "items": [
    { "seq": 1, "name": "截止阀", "spec": "DN25 PN16", "unit": "个", "qty": 10 }
  ],
  "detected_category": "阀门",
  "total": 90
}
```

### 2.3 新增接口 POST /analysis/anchor-review/confirm

人工确认/移除 pending 组。

```
body: { group_id: int, action: "confirm" | "reject" }
→ action=confirm: status → confirmed
→ action=reject:  DELETE group（级联删 items）
```

pending 全部处理后，矩阵可用。

### 2.4 bid_matrix.py — 修复多行覆盖

同一供应商同一锚点有多条报价时，取**单价最低**的一条进矩阵（或未来可聚合）。

```python
# 旧
quote_by_supplier[item.supplier_id] = qt

# 新
existing = quote_by_supplier.get(item.supplier_id)
if existing is None or (qt.unit_price or 0) < (existing.unit_price or 0):
    quote_by_supplier[item.supplier_id] = qt
```

### 2.5 bid_matrix.py — 只消费 confirmed 组

```python
# 旧：所有 confirmed 状态组
.filter(BidAlignmentGroup.status == "confirmed")

# 新（已是这个过滤，但需确认 pending 不混入）
# pending 不在 confirmed 里，天然隔离
```

## 三、前端变更（IndexView.vue）

### 3.1 步骤重组

| 步骤 | 旧 | 新 |
|------|----|----|
| Step 0 | 配置任务（项目+品类+供应商）| 配置任务（项目，品类可选） |
| Step 1 | 上传报价文件（采购清单作附件）| **上传采购清单**（必传，显示预览） |
| Step 2 | 锚点复核 or AI 对齐 | **上传供应商报价** |
| Step 3 | 比价结果 | **对齐核查（门禁）** |
| Step 4 | — | **比价矩阵** |

### 3.2 Step 1 — 采购清单上传 + 预览

- 上传 xlsx → 调 `/tender-list/preview` → 展示表格（品名/规格/单位/数量）
- 顶部显示自动识别品类，可下拉修改
- 预览确认后，状态保存到 `tenderPreview`，才显示"下一步"

### 3.3 Step 2 — 供应商报价（现有逻辑不变）

- 保留现有多文件拖入 + OCR + 供应商确认流程
- 所有文件 confirmed 后显示"开始匹配"（调 `/tender-list/match`）

### 3.4 Step 3 — 对齐核查（门禁改造）

- 调 `/anchor-review` 拿数据
- **高置信**：折叠列表，可展开看明细，无需操作
- **待确认（pending）**：
  - 逐条展示，不可跳过
  - 每条显示人话说明
  - 操作：「确认归入」/ 「移除此项」
  - 进度条：N/M 待确认项已处理
  - 全部处理完前，"生成比价矩阵"按钮不可用
- **清单外报价**：信息展示，无需操作

### 3.5 供应商名 fallback

`sup` 为 None 时显示 `供应商#${supplier_id}`，不留空白。
