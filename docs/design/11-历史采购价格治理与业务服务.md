# 历史采购价格治理与业务服务

> 状态：设计基线  
> 适用范围：`docs/项目资料/材料汇总`、客户补充版本、正式归档的历史采购价格，以及比价、邀标和供应商推荐对历史数据的消费。  
> 核心原则：历史采购价格不是一组可随意查询的 `Quote` 记录，而是一组经过来源、口径、实体和质量审核的业务事实。

## 1. 目标

本流程同时解决两个问题：

1. 把客户提供的历史 Excel 稳定、可追溯地整理为可复查的数据资产。
2. 为比价、邀标、供应商匹配和代理品牌匹配提供统一业务服务，而不是让各模块直接查询原始表或自行拼规则。

最终形成三类可消费事实：

- **历史价格事实**：某项目、某物料、某供应商在某日期和税价口径下的确认价格。
- **供应商履约事实**：供应商在哪些品类、项目和时间范围内有可信供货记录。
- **供应商-品牌证据**：供应商曾经报价、供货或被明确登记代理某品牌的证据；不同证据等级不得混为一谈。

## 2. 非目标与安全边界

- 原始 Excel、raw CSV 和清洗中间文件不得直接进入生产价格基准。
- 比价暂存数据 `BidSubmission` / `BidQuoteLine` 不自动成为历史采购价格。
- E2E、测试项目、演示数据和临时修复数据不得进入历史基准、供应商履历或品牌证据。
- 原始文件中的供应商名、品牌名不得自动创建或合并供应商主数据。
- “供应商曾报价某品牌”不等于“供应商获得该品牌正式代理授权”。
- 历史数据只能辅助邀标和评审，不替代供应商准入、代理授权核验和采购审批。

## 3. 数据目录与版本

现有 `docs/data` 根目录中的 CSV 和 `manifest.json` 视为 legacy v0，冻结保留，不覆盖生成。

新数据使用显式版本目录：

```text
docs/data/
├─ raw/
│  └─ YYYY-MM-DD/
│     ├─ manifest.json
│     ├─ source_registry.json
│     ├─ csv/
│     │  ├─ 不锈钢管/
│     │  ├─ 桥架/
│     │  ├─ 母线槽/
│     │  ├─ 配电箱/
│     │  ├─ 阀门/
│     │  └─ ...
│     └─ audits/
│        ├─ workbook_summary.json
│        ├─ source_version_diff.csv
│        └─ conversion_report.json
└─ curated/
   └─ v1/
      ├─ manifest.json
      ├─ categories/
      ├─ mappings/
      ├─ review/
      ├─ rejected/
      └─ reports/
```

规则：

- raw 目录只做可重复的格式转换，不修改业务含义。
- curated 目录存放清洗、分类和校验后的候选事实。
- 任何版本均不可原地覆盖；新来源或新规则必须产生新版本和差异报告。
- `manifest.json` 记录文件哈希、来源版本、转换参数、行列数、公式数、CSV 哈希和生成时间。

## 4. 来源登记

`source_registry.json` 是唯一来源选择清单。每份来源至少登记：

```json
{
  "source_id": "electrical-panel-2026-05-20",
  "category": "配电箱",
  "path": "docs/项目资料/用户反馈/2026-05-20/0配电箱.xlsx",
  "sha256": "...",
  "version_date": "2026-05-20",
  "status": "active",
  "supersedes": "electrical-panel-original",
  "authority": "customer_feedback",
  "notes": ""
}
```

来源状态：

- `active`：当前清洗采用的权威版本。
- `superseded`：被新版替代，但必须保留。
- `reference_only`：仅供比对，不能生成价格事实。
- `rejected`：来源错误或不可使用。

### 4.1 配电箱版本策略

配电箱当前存在两个版本：

- 原版：`docs/项目资料/材料汇总/0配电箱.xlsx`
- 客户补充版：`docs/项目资料/用户反馈/2026-05-20/0配电箱.xlsx`

处理规则：

1. 客户补充版作为 active 来源，原版标记为 superseded。
2. 两版都计算 SHA256，并生成 sheet、单元格和公式级差异报告。
3. 新版补充的品牌值进入 `brand_raw`。
4. 原版品牌列中的“新增”“利用原有箱体”等非品牌值，不得丢弃；迁移到 `box_status_raw` 或 `source_note`。
5. 公式单元格在 raw 层记录公式和缓存显示值；curated 价格事实只能使用经核验的显示值。

## 5. 清洗流水线

```text
来源登记
  -> 原始工作簿盘点
  -> raw CSV + manifest
  -> 多版本差异审计
  -> sheet/行类型识别
  -> 字段标准化
  -> 物料、供应商、品牌实体解析
  -> 价格与税口径校验
  -> 历史事实资格判定
  -> curated / review / rejected 分流
  -> 守恒与质量报告
  -> 人工批准发布
```

### 5.1 原始转换

- 每个 workbook/sheet 独立导出，不自行合并。
- `汇总` sheet 与项目明细 sheet 必须标注数据关系；未证明互斥前禁止同时聚合，以免重复计数。
- CSV 保留原始列名、原始值和来源坐标。
- 转换脚本必须由 `source_registry.json` 驱动，不允许写死旧目录。

### 5.2 行类型识别

每行至少分类为：

- `price_line`
- `component_line`
- `box_header`
- `subtotal`
- `grand_total`
- `fee`
- `formula`
- `remark`
- `empty`
- `invalid`

小计、合计、公式说明和章节标题不得进入历史单价样本。

### 5.3 字段标准化

同时保留 raw 和 normalized：

- 名称、规格、型号、材质、单位
- 数量、含税/不含税单价、合价、税率
- 供应商、品牌、项目、日期
- 品类扩展字段，例如阀门的 DN/PN/阀型，配电箱的箱号/回路/元件

禁止以 `(名称, 规格)` 作为全局唯一键。相同物料可能在不同系统、楼层、项目和供应商下合法重复。

### 5.4 配电箱专用模型

配电箱是层级 BOM，不能强行整理成一张普通材料价格表：

- `配电箱_箱级.csv`：项目、箱号、箱型、数量、整箱价格、品牌、状态。
- `配电箱_元件级.csv`：箱号、元件、规格、型号、品牌、数量、单价、合价。
- `配电箱_费用项.csv`：箱体、人工、管理费、辅材、小计等。

只有能证明为单独采购价格的元件行才能进入元件历史价格样本。整箱价格不得与元件单价混用。

## 6. 历史事实资格

一条记录只有满足以下条件，才可发布为 `historical_price_fact`：

- 来源为 active 且哈希可追溯。
- 行类型为有效价格行。
- 物料标准化结果明确，保留原始名称和规格。
- 价格大于零，币种明确。
- 税价口径明确；未知口径不得和含税/不含税样本混算。
- 单位和价格单位明确。
- 供应商解析结果为已确认实体，或明确标记为未知供应商。
- 不属于测试、E2E、演示、临时修复或被污染批次。
- 不存在未解释的算术冲突、合计污染或重复来源。
- 有 `source_file/source_sheet/source_row`，必要时有单元格坐标。

资格状态：

- `approved`：可用于价格、供应商和品牌业务服务。
- `price_only`：价格可信，但供应商或品牌证据不足。
- `supplier_only`：可证明供应商履历，但价格口径不适合做基准。
- `review`：待人工核验。
- `rejected`：禁止业务消费。

## 7. 标准事实契约

### 7.1 历史价格事实

```text
fact_id
material_id / canonical_material_key
raw_name / standard_name
raw_spec / normalized_spec
category / family / DN / PN / unit
project_id / project_name
supplier_id / supplier_raw_name
brand_id / brand_raw
quantity
unit_price_incl_tax / unit_price_excl_tax
tax_rate / tax_basis
quote_date
fact_status
source_id / source_file / source_sheet / source_row
quality_flags
```

价格基准必须按相近物料、规格、单位、税口径和时间范围计算。样本不足时返回无基准，不得退化为全品类最低价。

### 7.2 供应商履历证据

```text
supplier_id
category / material_family
project_id
first_seen_at / last_seen_at
approved_fact_count
project_count
recent_fact_count
price_sample_count
source_ids
```

报价次数、成交次数和中标次数必须分开。没有中标证据时，不得把“报价过”描述成“成交过”。

### 7.3 供应商-品牌证据

证据分级：

1. `authorized`：有授权书、代理证或客户确认资料。
2. `awarded`：中标或采购事实明确记录该供应商和品牌。
3. `quoted`：历史报价记录显示该供应商报价过该品牌。
4. `claimed`：供应商或投标文件自述，但未经独立核验。
5. `inferred`：系统从文本或上下文推断，只能用于候选提示。

```text
supplier_id
brand_id / brand_raw
category
evidence_level
project_id
valid_from / valid_to
source_id / source_ref
status
```

邀标页面必须显示证据等级。`quoted`、`claimed` 和 `inferred` 不得展示为“正式代理品牌”。

## 8. 业务服务边界

历史采购价格需要提供领域服务，而不是只有 CRUD。

### 8.1 HistoricalPriceService

职责：

- 按标准物料键、规格、单位、税口径和日期检索可信样本。
- 计算中位数、分位区间、样本量和数据新鲜度。
- 返回基准的来源项目、供应商覆盖和可追溯证据。
- 解释为什么无可靠基准。

建议接口：

```text
get_price_samples(material_signature, filters)
get_price_baseline(material_signature, tax_basis, as_of)
explain_price_baseline(baseline_id)
get_price_trend(material_signature, period)
```

### 8.2 SupplierEvidenceService

职责：

- 查询供应商在指定品类、物料族和项目类型下的可信履历。
- 区分报价、采购、中标和合作证据。
- 输出样本量、最近时间、项目覆盖和证据来源。

建议接口：

```text
get_supplier_history(supplier_id, scope)
find_suppliers_for_materials(material_signatures, scope)
get_supplier_coverage(supplier_id, material_signatures)
```

### 8.3 SupplierBrandEvidenceService

职责：

- 查询供应商与品牌之间的证据，而不是查询一个无来源的字符串列表。
- 支持“某供应商有哪些品牌证据”和“某品牌有哪些供应商证据”双向检索。
- 对证据等级、有效期、品类和来源进行过滤。

建议接口：

```text
get_brands_for_supplier(supplier_id, category, min_evidence_level)
find_suppliers_for_brands(brand_requirements, category)
explain_supplier_brand_evidence(supplier_id, brand_id)
```

### 8.4 InviteRecommendationService

邀标推荐组合以上服务：

1. 根据招标清单生成物料签名和品牌要求。
2. 用供应商履历召回候选供应商。
3. 用供应商-品牌证据核验品牌覆盖。
4. 用价格事实提供历史竞争力参考。
5. 返回证据和缺口，不自动创建供应商，不自动宣称代理授权。

推荐结果必须说明：

- 候选供应商为何被召回。
- 覆盖了哪些物料和品牌。
- 使用了多少 approved 历史事实。
- 哪些品牌仅为历史报价证据。
- 哪些物料没有历史供应商覆盖。

## 9. 统一消费规则

- 比价、仪表盘、供应商评分和邀标不得各自直接实现历史有效性过滤。
- 业务代码不得直接把 `Quote.brand` 聚合结果当作代理品牌。
- 所有历史业务查询必须通过统一服务，并默认只消费 approved/允许用途的事实。
- 当前 `valid_quote_filters()` 仅是最低数据库过滤，不构成完整归档资格。
- 任何历史事实重新清洗或重发版本后，价格基准和供应商/品牌证据必须可重建、可对账。
- 服务返回空结果时，调用方必须展示“证据不足”，不得回退到无范围的全库统计。

## 10. 发布与数据库写入

curated 文件通过验收后，才允许发布到业务数据库：

1. 备份生产数据库。
2. dry-run 输出新增、更新、拒绝、待审核和重复行清单。
3. 每条写入记录携带 `source_id`、数据版本和资格状态。
4. 事务内写入，任一守恒断言失败则回滚。
5. 不物理删除旧事实；使用 `superseded`、`polluted`、`excluded_from_ref` 等状态。
6. 发布后重建价格基准与证据索引，并核对样本数和来源数。

比价报价归档必须是显式用户操作：

```text
BidSubmission / BidQuoteLine
  -> 用户确认归档
  -> 归档质量门
  -> Quote / historical fact candidate
  -> 审核发布
```

## 11. 验收门

### raw 层

- 来源文件数量、sheet 数、行列数与工作簿守恒。
- 公式数量、缓存值和文件哈希已记录。
- 多版本来源有明确 active/superseded 关系。

### curated 层

- 每条记录有来源坐标。
- 小计、合计、公式和说明行未污染价格样本。
- 含税/不含税口径不混算。
- 重复记录和拒绝记录有报告。
- 配电箱箱级、元件级和费用项守恒。

### 服务层

- 测试/E2E/污染数据不会影响价格基准和供应商推荐。
- 无可靠同规格样本时返回空基准。
- 供应商-品牌结果包含证据等级和来源。
- 邀标推荐能解释供应商召回、品牌覆盖和数据缺口。
- 比价暂存不会自动污染历史价格或供应商主数据。

## 12. 分阶段实施

1. **原始资产重建**：修正转换脚本路径，建立 source registry，生成版本化 raw CSV 和 manifest。
2. **清洗与审计**：按品类建立 curator；优先处理阀门和配电箱，输出 review/rejected/守恒报告。
3. **统一历史服务门面**：先在现有 `Quote` 表之上实现服务层，替换各模块的直接聚合查询。
4. **供应商-品牌证据模型**：建立证据等级、来源和有效期；迁移现有报价品牌为 `quoted` 证据。
5. **邀标接入**：供应商推荐消费历史服务，展示证据，不把报价品牌冒充代理授权。
6. **正式发布**：审批后重建生产历史价格，并验证比价、邀标、供应商画像和仪表盘。
