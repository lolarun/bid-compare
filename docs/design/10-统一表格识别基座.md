# 10 - 统一表格识别基座（采购清单 + 报价清单共用）

## 目标与边界

采购清单（招标）与报价清单（投标）的 PDF 表格识别，收敛为**一套公共骨架** + 两侧 adapter（prompt + 钩子）。
公共骨架承担全部健壮性、来源证据与质量门机制；两侧只提供"哪些页/什么 prompt/什么 meta"。

**本次交付 = 一个任务，内部两段验收（0+1），公共基座在两条真实 PDF 链路都通过后才算完成。**
- 第 0 段：抽出骨架，招标接入，`test_extract_bidlist_real_pdf` 行为等价（回归护栏）。
- 第 1 段：报价接入，泰科龙真实 E2E 通过。
- 严禁只服务代码整洁、不改善报价交付的长期重构。报价侧本次将获得：expected_rows 重试门、质量报告、bbox 来源、PASS/REVIEW/BLOCKED、对账——均为实质交付改善。

**硬约束**：不修改数据库；不写固定页码/固定 seq/固定供应商逻辑；页面定位一律靠信号打分。

### 已知事实修正（来自本仓真实 E2E）
招标侧**不是成熟结构实现**：金桥招标 5 个清单页 TableGrid 使用率 0/5，全部 html_fallback。
它能成功是因为是干净文本型 PDF，LLM 直读 HTML。结构抽取层（转置/合并单元格/跨页续表）**尚未被任何真实样本验证**。
因此骨架抽取的是招标侧的**健壮性脚手架**，不是它的结构能力。

## 1. 公共 Schema：ExtractionDraft + QualityReport

识别链路输出 `ExtractionDraft`（识别结果，**未确认**），不直接生成领域对象：

```
识别 → ExtractionDraft → 用户核对确认 → TenderAnchor / BidQuoteLine
```

### ExtractionDraft

```python
@dataclass
class DraftRow:
    row_index: int
    row_type: str           # quote_line|subtotal|grand_total|section_header|remark|invalid
    raw_cells: dict          # 原始 OCR 单元格值（保留，不丢）
    fields: dict             # 标准化字段（§4 数据模型超集，见下）
    source_ref: dict         # {page, table, row, bbox}
    corrections: list        # [{field, raw, fixed, reason}] OCR 纠错审计
    validation_flags: list   # [arithmetic_mismatch, missing_price, tax_basis_conflict, ...]

# fields 键（两侧统一超集；缺失留空/None，不猜测）：
#   name spec model pressure materials unit qty
#   unit_price_incl_tax unit_price_excl_tax tax_rate
#   total_price_incl_tax total_price_excl_tax brand profession remark canonical

@dataclass
class ExtractionDraft:
    doc_type: str                  # "tender" | "quote"
    source_file: str
    page_count: int                # PDF 总页数
    processed_page_count: int      # 必须 == page_count（页数守恒）
    target_pages: list             # 命中的目标表格页（1-based）
    rows: list                     # [DraftRow]
    meta: dict                     # 两侧各自结构（招标品牌 / 报价供应商+总价）
    quality: "QualityReport"
    reconcile: dict | None         # 有 Excel 时内容对账；否则 None
```

### QualityReport（CLAUDE.md §6 DocumentQualityReport 落地）

```python
@dataclass
class QualityReport:
    status: str                    # PASS | REVIEW | BLOCKED
    total_pages: int
    processed_pages: int
    truncated: bool                # 永远显式；命中任何上限都 True 并降级
    candidate_table_pages: list
    extracted_pages: list
    page_metrics: list             # [{page, role, input_mode, fallback_reason,
                                   #   expected_rows, extracted_rows, thinking_retry, tiled}]
    quote_line_count: int
    subtotal_count: int
    grand_total_count: int
    source_ref_coverage: float     # page/table/row 覆盖率
    bbox_coverage: float           # bbox 单列覆盖率（增量推进，不达 100% 不阻断 REVIEW）
    qty_parse_rate: float
    price_parse_rate: float
    arithmetic_consistency_rate: float   # qty×单价≈合价
    tax_basis_consistency: bool
    declared_total: float | None
    declared_total_diff: float | None    # 明细合计 vs 声明总价
    seq_missing: list
    seq_duplicate: list
    blocking_reasons: list          # 为何 BLOCKED/REVIEW

# 状态判定（阈值集中配置，§6）：
#   BLOCKED：truncated 且未处理完；有报价数据但 quote_line=0；全行被跳过；
#            总计/小计污染商品行；声明总价差异超阈值且无人工确认；关键金额行无来源。
#   REVIEW ：expected/extracted 缺口、bbox 未满、html_fallback 占比高、算术一致率 < 阈值。
#   PASS   ：以上皆无。
```

### Adapter 契约（最小：2 钩子 + 1 prompt + 1 可选 meta）

```python
@dataclass
class RecognizeAdapter:
    doc_type: str
    detect_pages: Callable[[list[str]], list[int]]   # 钩子①：哪些页是目标表
    row_prompt: str                                   # ②：Stage-2 抽取 prompt
    extract_meta: Callable | None = None              # ③可选：两侧各自实现，不统一 prompt

TenderAdapter: detect_pages=_score_page, row_prompt=TENDER_BIDLIST_PROMPT,
               extract_meta=招标情况表(品牌要求+投标单位品牌)
QuoteAdapter:  detect_pages=page_classifier(QUOTE_TABLE/UNKNOWN), row_prompt=QUOTE_S2_TABLE_PROMPT,
               extract_meta=封面/汇总(供应商+声明总价+税价口径)
```

行 → DraftRow 的标准化在骨架内统一完成（不是钩子）；映射到领域对象在用户确认之后。

### 骨架固定流程

```
recognize_tables:
  render 全页 (MAX_PAGES_UNLIMITED, 页数守恒)
  ocr_pages_with_roles → (PageClassification, html)[]   # 角色 + 诊断
  target = adapter.detect_pages(htmls)
  for page in target:
      llm_input, expected_rows, input_mode, reason = build_llm_input(html)   # TableGrid/fallback
      data = llm_call(adapter.row_prompt, llm_input)
      if extracted < expected_rows * 0.7:                # expected_rows 完整性检查
          data = retry(...)                              # 重试升级接口（见 §3）
      rows += [to_draft_row(r, source_ref+bbox)]
  meta = adapter.extract_meta(...) if adapter.extract_meta else {}
  quality = compute_quality(rows, page_metrics, meta)    # PASS/REVIEW/BLOCKED
  reconcile = reconcile_vs_excel(rows) if xlsx else None
  return ExtractionDraft(...)
```

## 3. Adaptive tiling 触发条件（**本次交付内实现**）

**决策（2026-06-19）**：泰科龙整页 OCR 已知失败、裁剪后明显改善，且有逐行标准答案可验收，数据依据已具备。
tiling 作为当前交付内的条件降级路径，不是未来增量。

**最小可靠实现（本次）**：
1. 根据页面宽高比判断方向（landscape: W>H；portrait: H>W），选横向条带切片；
2. 切 N 条（默认 4），每条重叠 10-15%；
3. 每条记录在原页的 bbox_pct = (x0, y0, x1, y1) 比例坐标；
4. 每条独立 OCR → HTML → LLM 提取 raw_items；
5. 所有条 raw_items 按 tile_index 排序，以 (seq, name[:10], spec[:8]) 为 key 去重（保留先出现的）；
6. 重建统一 raw_items 列表，再做字段语义抽取和质量校验；
7. 每个 draft_row.source_ref 追加 `tile_bbox` 记录所属切片区域。

**触发条件**（任一满足才触发，普通页不触发）：
- thinking-retry 后仍 `extracted_rows < expected_rows * 0.7`；
- `input_mode == html_fallback` 且 `extracted_rows == 0` 且页面含价格信号。

**重试耗尽策略**：
- thinking-retry → tiling 均失败 → 该页进入 `REVIEW`（extracted_rows 记实际值）；
- 如果目标页中有 > 30% 页进入 REVIEW → 文档升级为 `BLOCKED`；
- 禁止输出伪完整结果（不得填充默认值）。
