# 设计：采购清单品类识别 + 多品类拆分 + match 自动落 session

> 状态：待确认 · 2026-06-17 · 关联问题：项目63 复核矩阵/比价矩阵 409、品类下拉误显示"给排水"

## 背景与根因

三个问题同根，本质是**"专业(profession)"与"品类(category)"两个概念在上传环节串了**，且 session 持久化有流程漏洞。

层级关系（已存在于 `IndexView.vue:34`）：

| 专业 profession | 品类 category（物料主数据 / 匹配 / session 都用这个） |
|---|---|
| 电气 | 桥架、母线槽、配电箱 |
| 给排水 | **阀门**、不锈钢管、水箱、潜水泵 |
| 暖通 | 风口风阀、风机盘管、空调泵 |

三个根因：

1. **品类自动识别错误**（Q2）：`tender-list/preview`（analysis.py:619）把 Excel 的**专业列**(给排水)当作 detected_category 返回，而下拉选项是10个**品类**，导致游离值"给排水"，且 `Material.category=="给排水"` 匹配不到任何报价。
2. **不支持多品类**（Q1）：一个 TenderListSession 绑定单一 category，匹配只按该 category 过滤报价；混品类清单会把所有锚点塞进一个品类。
3. **session 流程漏洞**：`/tender-list/match` 文件路径只链接已存在 session、从不创建；用户跳过"确认采购清单版本"按钮就进第3步时，session 永远为空 → 复核矩阵和比价矩阵均 409。

## 决策（已与用户确认）

- Q2 → **从品名推断品类**
- Q1 → **按品类拆分多个 session**
- 漏洞 → **后端 match 时自动落 session**

---

## 方案

### 1. 品类分类器（新）`apps/api/services/category_classify.py`

```python
def classify_category(name: str, spec: str = "", pressure: str = "", material: str = "") -> str:
    """品名→10品类之一，识别不到返回 ""。"""
```

- **阀门**：复用 `extract_valve_canonical(...)`，`valve_type` 非空即判为阀门（覆盖 Y型过滤器/倒流防止器/各类阀，现有 naive 子串匹配漏判这些）。
- 其余9类：维护关键词表（桥架/母线槽/配电箱/不锈钢管/水箱/潜水泵/风口/风阀/风机盘管/空调泵…），子串/正则命中即判。
- 顺序：先阀门 canonical，再关键词表，最后回退现有 `_infer_category`。
- 单测覆盖：Y型过滤器→阀门、冲洗取水阀→阀门、减压型倒流防止器→阀门、电缆桥架→桥架等。

### 2. preview 端点改造（analysis.py:586）

每个 anchor 增加 `category` 字段（= classify 结果）；返回新增 `category_breakdown`：

```jsonc
{
  "items": [{..., "category": "阀门"}, ...],
  "category_breakdown": {"阀门": 88, "不锈钢管": 2},   // 新增
  "detected_category": "阀门",   // = breakdown 多数派（替代旧的取 profession[0]）
  "total": 90
}
```

`profession` 字段保留（信息性），但不再用于 detected_category。

### 3. confirm 端点改造：按品类拆分多 session（analysis.py:1344）

输入仍是全部 anchors；后端按 `anchor.category` 分组，**每个品类建一个 TenderListSession**：

- 单品类清单（如本例全阀门）→ 1 个 session，行为与今天一致。
- 多品类 → N 个 session，各自 `anchors_json` 只含本品类锚点，`is_current=True/status=confirmed`，版本号各品类独立递增。
- 返回 `{"sessions": [{"category": "...", "id": ..., "version": ..., "anchors_total": ...}], ...}`。

### 4. match 自动落 session（analysis.py:659，堵漏洞）

文件上传路径：解析后若该 (project, category) 无 current session，则**用解析出的该品类锚点自动建 confirmed session** 再匹配。保证"任何从文件跑过匹配的项目都有 session"，项目63 重跑即自愈。

多品类时：match 逐品类建 session + 逐品类匹配。

### 5. 前端 Step 2 改造（IndexView.vue）

- 上传后展示 `category_breakdown`：「识别到 阀门×88、不锈钢管×2」。
- 单品类：维持现状（下拉预选识别品类）。
- 多品类：提示将按品类拆分为 N 份，确认即建 N 个 session。
- 下拉 `tenderCategory` 仅在识别为空/需人工纠正时启用。

### 6. 下游（Step 3 复核 / Step 4 比价）

`/bid-matrix`、`/anchor-review/matrix`、export、finalize 已全部按 (project, category) 工作 —— 多品类时新增**品类切换器**（顶部 segmented），逐品类复核/比价。无需改这些接口本身。
