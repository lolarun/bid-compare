# P0 数据模型与写链路重构

> **状态**：v3 设计稿，待确认后再改代码  
> **日期**：2026-06-18  
> **范围**：比价链路数据污染根因修复 · 主数据隔离 · 供应商别名体系 · 历史数据清洗

---

## 一、污染根因分析

### 1.1 `material_class` 与 `category` 混用

**根因**：`tender_pdf.py:404` 将 OCR 原文 `material_class="水阀门"` 单独返回，`IndexView.vue:232` 将其错误赋值给 `tenderCategory`，导致后续匹配在错误品类下执行。

真实数据流：
- `items[*].category` 经 `anchor_to_json(a, default_category="阀门")` 已正确设为 "阀门" ✓
- `material_class` 是招标文件原文，仅作展示，不是系统品类键

**修复方向**：API 新增 `detected_category` 字段（从 `items[*].category` 多数统计），前端 `tenderCategory` 只能从该字段赋值，`material_class` 仅在 Step 2 结论卡片展示。

---

### 1.2 `batch-confirm` 污染主数据三张表

| 代码位置 | 污染行为 |
|---------|---------|
| `quotes.py:360–362` | 无匹配时 `INSERT Supplier`，模糊匹配阈值 0.75 对短名称不稳定 |
| `quotes.py:544–557` | (category, standard_name, spec) 未命中时 `INSERT Material` |
| `quotes.py:626–648` | 每次入库直接 `INSERT Quote`，影响参考价统计 |

---

### 1.3 供应商别名体系缺失

同一供应商在不同文件中以多种形式出现，无历史记忆，重复建档。

---

### 1.4 `BidAlignmentItem.quote_id` 绑定 `quotes` 表

现有 `quote_id NOT NULL`，导致矩阵依赖 `quotes` 表，逼使用户先归档才能比价。正确的链路是比价全程读 `BidQuoteLine`，归档历史价格是独立的可选动作。

---

### 1.5 参考价查询无统一有效性过滤

`refresh_material_baselines()` 及所有统计查询直接读取全部 `quotes` 行，无法排除被污染的投标价，导致参考价失真。

## 四、数据模型方案（To-Be）

### 4.1 新建 `bid_submissions`

```
bid_submissions
  id                INTEGER  PK AUTOINCREMENT
  job_id            TEXT     NOT NULL → extraction_jobs(id)
  supplier_id       INTEGER  NOT NULL → suppliers(id)
                    -- 必须由用户从现有列表选定，禁止为空，禁止系统自动创建
  supplier_raw_name TEXT     NOT NULL DEFAULT ''    -- OCR 原始名留存（溯源用）
  project_id        INTEGER  → projects(id)          -- 可为 NULL
  batch_id          TEXT     NOT NULL UNIQUE         -- 幂等键
  status            TEXT     NOT NULL DEFAULT 'pending'
                    -- pending / confirmed / archived / partially_archived / rejected
  bid_status        TEXT     NOT NULL DEFAULT ''
  created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
  updated_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
```

状态机：
```
pending → confirmed（采购员审核通过）
        → rejected（采购员拒绝）
confirmed → archived（全部行归档成功）
          → partially_archived（部分行因 material_id=NULL 跳过）
```

### 4.2 新建 `bid_quote_lines`

```
bid_quote_lines
  id                  INTEGER  PK AUTOINCREMENT
  submission_id       INTEGER  NOT NULL → bid_submissions(id) ON DELETE CASCADE
  material_id         INTEGER  → materials(id)   -- 可为 NULL；NULL 不影响比价，归档时跳过
  raw_name            TEXT     NOT NULL DEFAULT ''
  standard_name       TEXT     NOT NULL DEFAULT ''
  category            TEXT     NOT NULL DEFAULT ''
  spec                TEXT     NOT NULL DEFAULT ''
  unit                TEXT     NOT NULL DEFAULT ''
  qty                 REAL
  unit_price          REAL
  unit_price_excl_tax REAL
  tax_rate            REAL
  total_price         REAL
  brand               TEXT     NOT NULL DEFAULT ''
  brand_tier          TEXT     NOT NULL DEFAULT ''
  remark              TEXT     NOT NULL DEFAULT ''
  quote_date          TEXT     NOT NULL DEFAULT ''
  canonical           JSON     -- 结构化键（valve_type/DN/PN），用于项目内软对齐
  extraction_meta     JSON     -- 完整 OCR 证据
  deviation_pct       REAL
  alert_level         TEXT     NOT NULL DEFAULT ''
  archived_quote_id   INTEGER  → quotes(id)       -- 归档后回填，NULL=未归档
  created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP

INDEX ix_bql_submission (submission_id)
INDEX ix_bql_material   (material_id)
```

**`material_id=NULL` 的对齐能力**：项目内对齐和矩阵通过 `canonical`（valve_type/DN/PN）+ `standard_name` + `spec` 做软对齐，不需要 `material_id`。只有显式归档历史价格才强制要求 `material_id IS NOT NULL`。

### 4.3 新建 `supplier_aliases`

```
supplier_aliases
  id               INTEGER  PK AUTOINCREMENT
  supplier_id      INTEGER  NOT NULL → suppliers(id) ON DELETE CASCADE
  alias            TEXT     NOT NULL DEFAULT ''
                   -- 原始别名文本（保留供展示/溯源，不做唯一约束）
  normalized_alias TEXT     NOT NULL
                   -- 规范化后文本（见噪声清除规则）
  alias_type       TEXT     NOT NULL DEFAULT 'historical'
                   -- legal_name / short_name / filename / historical
  active           INTEGER  NOT NULL DEFAULT 1   -- 1=启用，0=禁用
  confidence       REAL     NOT NULL DEFAULT 1.0
  created_by       TEXT     NOT NULL DEFAULT ''  -- 'system_init' / 'user:xxx' / 'ocr_auto'
  source_reference TEXT     NOT NULL DEFAULT ''  -- 如 "filename: 凯硕新正投标文件.pdf"
  created_at       DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP

UNIQUE (supplier_id, normalized_alias, alias_type)
  -- 同一供应商可保留多条不同来源的证据记录
  -- "凯硕新正"(short_name) 与 "凯硕新正投标文件.pdf"(filename,去噪后→凯硕新正) 可同时存在于同一 supplier

INDEX ix_sa_normalized (normalized_alias)   -- 普通索引，跨供应商查询时用
INDEX ix_sa_supplier   (supplier_id)
```

**唯一约束设计说明**：

`UNIQUE(supplier_id, normalized_alias, alias_type)` 而非 `UNIQUE(normalized_alias)`：
- 允许同一供应商保留多条不同 `alias_type` 的证据（`short_name="凯硕新正"` 和 `filename="凯硕新正"`）
- 允许同一 `normalized_alias` 在排查阶段暂时指向多家供应商（`ambiguous` 状态，需人工解决）

**当 `normalized_alias` 命中多家不同 `supplier_id` 时**：
- 返回 `{"error": "supplier_ambiguous", "candidates": [{supplier_id, name, alias_type}]}`
- 禁止自动选择，由前端展示候选列表供用户手动选定
- 用户选定后，该别名按 `alias_type='historical'` 写入选定的 supplier，其他 supplier 的同 `normalized_alias` alias 标记 `active=0`

**文件名噪声清除规则**（生成 `normalized_alias` 前执行）：

按以下顺序处理，结果转小写并去首尾空格：
1. 去文件扩展名：`.pdf` `.xlsx` `.xls` `.docx` `.doc`
2. 去噪声词：`投标文件` `报价单` `报价文件` `采购清单` `招标文件` `第一轮` `第二轮` `第一次` `第二次` `终稿` `定稿` `修改版` `最终版` `v1` `v2` `v3`
3. 去日期模式：`\d{4}[-_年]\d{1,2}[-_月]\d{1,2}[日]?` 及 `\d{6,8}`
4. 去中英文括号中仅含空白的空串

**7 层查找优先级**（`_resolve_supplier()` 函数）：

| 层 | 方式 | 说明 |
|----|------|------|
| 1 | `supplier_id` 直接传入 | 用户在前端手动选择（最高优先级） |
| 2 | `Supplier.name` 精确匹配 | 主数据原始名称 |
| 3 | `alias_type='legal_name'` `normalized_alias` 精确匹配 | 营业执照全称 |
| 4 | `alias_type='short_name'` `normalized_alias` 精确匹配 | 日常简称 |
| 5 | `alias_type='filename'` `normalized_alias` 精确匹配（噪声清除后） | 文件名来源 |
| 6 | `alias_type='historical'` `normalized_alias` 精确匹配 | 历史 OCR 确认 |
| 7 | `difflib` 模糊匹配 ≥ 0.85（全部 active aliases + `Supplier.name`） | 返回候选列表，不自动匹配 |

层 1–6 唯一命中：直接返回 `supplier_id`。  
层 1–6 无命中，层 7 有候选：返回 `{"error": "supplier_ambiguous", "candidates": [...]}` — 用户手动选。  
层 7 也无命中：返回 `{"error": "supplier_not_found"}` — 前端提示去供应商管理新建，比价流程禁止创建。

**别名种子数据**（通过迁移脚本写入，不写在业务 if/else 中）：

仅将 **现有 `suppliers` 表中已存在** 的供应商的已知别名形式写入。

**正确的别名来源**（`Quote.extraction_meta_json.raw_material` 是物料原文，不是供应商名称，禁止用于生成供应商别名）：

| 来源 | 字段路径 | alias_type |
|------|---------|------------|
| 主数据名称本身 | `Supplier.name` | `legal_name` 或 `short_name`（由脚本判断长度/格式） |
| OCR 识别供应商名 | `ExtractionJob.result.supplier_name` / `ExtractionJob.context.supplier_name` | `historical` |
| 报价文件名（去噪后） | `ExtractionJob.filename` → 噪声清除 → `normalized_alias` | `filename` |
| 人工确认记录 | 手动录入 | 任意类型，`created_by='user:xxx'` |

不得将未经历史数据证明的名称（即在 `ExtractionJob` 或 `Supplier` 中不存在对应记录时）写入种子。

迁移脚本逻辑（见 §5.2 Phase 1）：
1. 查询 `suppliers` 表所有行，对每行用 `Supplier.name` 生成 `alias_type='legal_name'` 种子
2. 查询全部 `ExtractionJob`，按 `context.supplier_id` / `result.supplier_id` 关联到已知 `supplier_id`，从 `result.supplier_name`、`context.supplier_name` 生成 `historical` 类型种子，从 `filename` 经噪声清除生成 `filename` 类型种子
3. 发现冲突（同 `normalized_alias` 经规范化后匹配到多个 supplier）时，写入冲突报告文件，不自动处理

### 4.4 重建 `bid_alignment_items`（SQLite 全表重建）

**现状**：`quote_id INTEGER NOT NULL`，无法仅通过 `ADD COLUMN` 改为 nullable。

**重建目标**：

```
bid_alignment_items（重建后）
  id                  INTEGER  PK AUTOINCREMENT
  group_id            INTEGER  NOT NULL → bid_alignment_groups(id) ON DELETE CASCADE
  quote_id            INTEGER  → quotes(id)          -- 可为 NULL（历史路径）
  bid_quote_line_id   INTEGER  → bid_quote_lines(id) -- 可为 NULL（新路径）
  supplier_id         INTEGER  → suppliers(id)
  action              TEXT     DEFAULT 'align'
  spec_note           TEXT     DEFAULT ''
  agg_total           REAL
  agg_qty             REAL
  name_note           TEXT     DEFAULT ''
  created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP

  CHECK (
    (quote_id IS NOT NULL AND bid_quote_line_id IS NULL)
    OR
    (quote_id IS NULL AND bid_quote_line_id IS NOT NULL)
  )  -- 两者必须且只能有一个非空

UNIQUE INDEX ix_align_item_group_quote   (group_id, quote_id)         WHERE quote_id IS NOT NULL
UNIQUE INDEX ix_align_item_group_bql     (group_id, bid_quote_line_id) WHERE bid_quote_line_id IS NOT NULL
```

**完整重建步骤（SQLite 协议）**：

```
步骤 0：备份
  cp data/mempas.db data/mempas-before-p0-YYYY-MM-DD.bak
  -- 在开始任何 DDL 前执行，不可跳过

步骤 1：记录迁移前行数（校验基线）
  SELECT COUNT(*) FROM bid_alignment_items;                → 记为 N_before
  SELECT COUNT(*) FROM bid_alignment_groups;               → 记为 G_before
  SELECT COUNT(*) FROM quotes WHERE id IN
    (SELECT quote_id FROM bid_alignment_items);            → 记为 FK_before

步骤 2：PRAGMA foreign_keys = OFF
  -- SQLite 重建表期间必须临时关闭外键检查

步骤 3：CREATE TABLE bid_alignment_items_new (...)
  -- 含全部新字段定义和 CHECK 约束（见上）
  -- 不含 UNIQUE INDEX（下一步创建）

步骤 4：INSERT INTO bid_alignment_items_new
  SELECT id, group_id, quote_id, NULL as bid_quote_line_id,
         supplier_id, action, spec_note, agg_total, agg_qty, name_note, created_at
  FROM bid_alignment_items;
  -- 全量迁移，bid_quote_line_id 初始值为 NULL

步骤 5：校验行数
  SELECT COUNT(*) FROM bid_alignment_items_new;            → 必须等于 N_before
  如果不相等：ROLLBACK（见回滚方案）

步骤 6：DROP TABLE bid_alignment_items

步骤 7：ALTER TABLE bid_alignment_items_new RENAME TO bid_alignment_items

步骤 8：CREATE UNIQUE INDEX ix_align_item_group_quote
  ON bid_alignment_items(group_id, quote_id)
  WHERE quote_id IS NOT NULL;

步骤 9：CREATE UNIQUE INDEX ix_align_item_group_bql
  ON bid_alignment_items(group_id, bid_quote_line_id)
  WHERE bid_quote_line_id IS NOT NULL;

步骤 10：PRAGMA foreign_keys = ON

步骤 11：外键完整性校验
  -- 检查所有旧数据的 quote_id 仍有效
  SELECT COUNT(*) FROM bid_alignment_items bai
  LEFT JOIN quotes q ON bai.quote_id = q.id
  WHERE bai.quote_id IS NOT NULL AND q.id IS NULL;         → 必须为 0
  
  SELECT COUNT(*) FROM bid_alignment_items bai
  LEFT JOIN bid_alignment_groups g ON bai.group_id = g.id
  WHERE g.id IS NULL;                                      → 必须为 0

步骤 12：最终行数守恒校验
  SELECT COUNT(*) FROM bid_alignment_items;                → 必须等于 N_before
```

**回滚方案（步骤 5 失败或步骤 11 不为 0）**：

```
PRAGMA foreign_keys = OFF;
DROP TABLE IF EXISTS bid_alignment_items_new;
DROP TABLE IF EXISTS bid_alignment_items;
ALTER TABLE bid_alignment_items_bak RENAME TO bid_alignment_items;  -- 如已重命名
PRAGMA foreign_keys = ON;
-- 若已过 DROP 步骤：从备份文件恢复
cp data/mempas-before-p0-YYYY-MM-DD.bak data/mempas.db
```

重建失败时**禁止**部署 Phase 2/3 代码。

### 4.5 `archive-prices` 端点返回格式

```
POST /quotes/bid-submissions/{id}/archive-prices

响应：
{
  "submission_id": 42,
  "eligible_count": 30,      -- submission 中全部 BidQuoteLine 行数
  "archived_count": 27,      -- 本次成功写入 Quote 的行数（含历史幂等命中）
  "skipped_count": 3,        -- 跳过的行数
  "skipped_lines": [
    {"line_id": 101, "raw_name": "DN50 蝶阀",  "reason": "material_id is null"},
    {"line_id": 105, "raw_name": "安装费",     "reason": "material_id is null"},
    {"line_id": 112, "raw_name": "蝶阀DN65", "reason": "duplicate archived_quote_id already set"}
  ],
  "status": "archived" | "partially_archived" | "no_eligible"
}

状态规则：
  archived           → skipped_count == 0
  partially_archived → skipped_count > 0 AND archived_count > 0
  no_eligible        → archived_count == 0
  
BidSubmission.status 同步更新为响应中的 status 值（不会出现 "archived" 掩盖跳过）
```

### 4.7 统一"有效历史报价"查询条件

**问题**：`refresh_material_baselines()`、供应商推荐、历史价格统计、偏差计算各自直接查询全部 `quotes`，无法共同排除污染记录，且维护分散。

**解决方案**：在 `apps/api/services/quote_filters.py`（新建）中定义一个共享查询构建器，所有涉及参考价的模块调用该函数，不得直接查询裸 `quotes` 表。

查询条件（以 SQLAlchemy 表达）：

```
有效历史报价 = quotes 满足以下全部条件：
  1. bid_status NOT IN ('polluted', 'excluded_from_ref', 'test')
  2. supplier_id 对应的 suppliers.merge_status = 'active'
     （即不关联已合并或停用的供应商）
  3. unit_price IS NOT NULL AND unit_price > 0
```

所有以下场景必须调用此共享函数（不得绕过）：
- `refresh_material_baselines()` — 参考价重算
- `build_anchor_review_matrix()` — 矩阵中显示的历史价格参考
- 供应商推荐（`BidInvitation` 评分）
- `GET /materials/{id}` 中返回的 `ref_price_*` 字段

### 4.8 修复 `detected_category` 字段

后端 `tender_pdf.py` 返回结构新增 `detected_category`：
- 从 `items[*].category` 做 `Counter` 统计
- 多数值 > 60% 时填充（如 "阀门"），否则返回 `""`（前端提示手动选择）
- `material_class` 保持原样返回，仅作展示

前端 `IndexView.vue` `onTenderJobDone` 修复：
```typescript
// 旧（错误）：tenderCategory.value = r.material_class
// 新（正确）：
if (!tenderCategory.value && r.detected_category) {
  tenderCategory.value = r.detected_category   // "阀门"
}
// r.material_class 只用于 Step 2 结论卡片的"招标原文品类"展示
```

## 五、迁移与切换方案

### 5.1 总体原则

**禁止 dual-write**：Phase 2/3 为一次性硬切，部署后 `batch-confirm` 立即只写暂存层，不再写 `quotes` / `materials` / `suppliers`。

**清洗顺序（用户已确认）**：
1. 关闭旧写入路径（Phase 2/3 部署）
2. 运行 dry-run 历史数据审计
3. 人工确认供应商合并映射
4. 执行清洗和参考价重算

---

### 5.2 Phase 1 — 仅 DDL（可独立部署）

以下变更全部为 additive，不破坏现有功能：

```
1. CREATE TABLE bid_submissions
2. CREATE TABLE bid_quote_lines  （含两个索引）
3. CREATE TABLE supplier_aliases （含 UNIQUE(supplier_id, normalized_alias, alias_type) 和普通索引）
4. ALTER TABLE suppliers ADD COLUMN merge_status TEXT NOT NULL DEFAULT 'active'
5. ALTER TABLE suppliers ADD COLUMN merged_into_supplier_id INTEGER REFERENCES suppliers(id)
6. bid_alignment_items 全表重建（按 §4.4 步骤 0–12 执行）
   -- 此步骤为 SQLite 重建，需离线执行，执行前必须备份
```

Phase 1 部署后立即验证：
- `bid_alignment_items` 行数 = 迁移前 N_before
- 所有 `quote_id` 外键有效（步骤 11 查询结果为 0）

## 六、历史数据清洗

### 6.1 清洗原则

- **不直接删除**：标记 `merge_status='merged'`/`'inactive'`、`bid_status='excluded_from_ref'`，保留可追溯。
- **dry-run 优先**：默认 `--dry-run`，输出报告，人工确认后执行。
- **幂等**：脚本可重复运行。
- **Quote 是证据，不是信任来源**：历史 Quote 记录本身可能被污染，需结合多维信号判断。
- **不得仅凭字符串相似度自动合并**：人工确认是充分条件。

### 6.3 执行合并（`scripts/merge_suppliers.py`）

```
输入：
  --merge-plan FILE    人工填写 human_verdict 后的 duplicate_clusters.csv
  --db PATH            数据库路径
  --dry-run            默认，仅输出 SQL 和影响行数
  --execute            实际写库（需显式传入）

合并操作（每个簇，仅 conservation_ok=True 的簇才执行）：

  校验阶段：
    重新运行 conservation_check，不通过则跳过并告警

  外键迁移阶段（全部覆盖，不遗漏）：
    UPDATE quotes            SET supplier_id = canonical_id WHERE supplier_id IN (dup_ids)
    UPDATE bid_submissions   SET supplier_id = canonical_id WHERE supplier_id IN (dup_ids)
    UPDATE bid_alignment_items SET supplier_id = canonical_id WHERE supplier_id IN (dup_ids)
    UPDATE bid_invitations   SET supplier_id = canonical_id WHERE supplier_id IN (dup_ids)
    -- 其他含 supplier_id 外键的表（迁移前通过 PRAGMA foreign_key_list 全量枚举）

  alias 迁移：
    INSERT INTO supplier_aliases (supplier_id, alias, normalized_alias, alias_type, ...)
    SELECT canonical_id, alias, normalized_alias, alias_type, ...
    FROM supplier_aliases WHERE supplier_id IN (dup_ids) AND active = 1
    ON CONFLICT(supplier_id, normalized_alias, alias_type) DO NOTHING
    -- 将各 duplicate 的 alias 全部迁移至 canonical

  标记 duplicate：
    UPDATE suppliers
    SET merge_status='merged', merged_into_supplier_id=canonical_id
    WHERE id IN (dup_ids)

  JSON 快照处理：
    不改写 BidMatrixVersion.matrix_json 等 JSON 字段（历史快照只读）
    输出 json_snapshot_impact.csv：记录哪些快照含被合并的 supplier_id，供人工知悉

  执行后校验（合并后再次运行 conservation_check，必须仍为 True）

输出：
  merge_execution_log_YYYY-MM-DD.csv（每行操作，含受影响行数）
  json_snapshot_impact.csv
```

### 7.1 生产库取回

**步骤一：确认环境状态**

登录生产服务器，记录以下信息（写入 `snapshot_manifest.json`）：

server_host       101.37.166.68

**步骤二：创建一致性快照（必须使用 SQLite backup API）**

使用以下任一方式：

方式 A — `sqlite3` 命令行（推荐）：

方式 B — Python `sqlite3.Connection.backup()`（脚本中调用）：
```python
import sqlite3
src = sqlite3.connect("/opt/mempas/data/mempas.db")
dst = sqlite3.connect("/opt/mempas/data/mempas-snapshot-<timestamp>.db")
src.backup(dst)
```

**步骤三：记录基线校验值（写入 `snapshot_manifest.json`）**

row_counts:

  materials        SELECT COUNT(*) FROM materials
  bid_alignment_items  SELECT COUNT(*) FROM bid_alignment_items
  supplier_aliases     SELECT COUNT(*) FROM supplier_aliases（若已建）
schema_version     （SELECT name FROM sqlite_master WHERE type='table' ORDER BY name）
```

**步骤四：将快照 scp 至本地，原始快照只读保存**

```

- 比价流程：上传 PDF → 选择供应商 → 校对暂存 → 对齐 → 矩阵 → 导出（全流程不报错）
- 导出 Excel：历史矩阵版本仍可正常下载

### 7.4 生产回写包构建

**禁止**将 `production-cleaned.db` 文件直接覆盖生产库。

运行构建脚本，生成 `fix_package/` 目录：
```
python scripts/build_production_fix_package.py \
  --original data/production-cleanup-<ts>/production-original-<ts>.db \
  --cleaned  data/production-cleanup-<ts>/production-cleaned-<ts>.db \
  --manifest data/production-cleanup-<ts>/snapshot_manifest.json \
  --merge-plan data/production-cleanup-<ts>/merge_plan.csv \
  --out data/production-cleanup-<ts>/fix_package/
```

`fix_package/` 内容：

| 文件 | 说明 |
|------|------|
| `apply_cleanup.sql` | 参数化 SQL 脚本，仅含 UPDATE/INSERT 语句（无 DROP/DELETE），单事务包裹 |
| `rollback_cleanup.sql` | 回滚脚本（逆向操作，还原合并标记、还原 supplier_id 外键） |
| `approved_merge_plan.json` | 人工批准的合并计划（含 cluster_id、canonical_id、dup_ids、conservation_ok） |
| `approved_exclusions.json` | 批准标记为 `excluded_from_ref` 的 batch_id 列表 |
| `expected_before.json` | 执行前生产库应有的行数/金额快照（从 snapshot_manifest.json 派生） |
| `expected_after.json` | 执行后预期的行数/金额快照（从 working 副本的 after 报告派生） |
| `SHA256SUMS` | 全部文件的 SHA256（含 apply_cleanup.sql 和 rollback_cleanup.sql） |
| `OPERATIONS.md` | 执行手册（维护窗口流程、每步命令、校验方法、回滚触发条件） |

`apply_cleanup.sql` 结构示意：
```sql
BEGIN TRANSACTION;

-- 1. 外键迁移
UPDATE quotes SET supplier_id = :canonical_id WHERE supplier_id IN (:dup_ids);
UPDATE bid_submissions SET supplier_id = :canonical_id WHERE supplier_id IN (:dup_ids);
UPDATE bid_alignment_items SET supplier_id = :canonical_id WHERE supplier_id IN (:dup_ids);
UPDATE bid_invitations SET supplier_id = :canonical_id WHERE supplier_id IN (:dup_ids);

-- 2. 别名迁移
INSERT INTO supplier_aliases (...) VALUES (...) ON CONFLICT(...) DO NOTHING;

-- 3. 标记已合并/停用供应商
UPDATE suppliers SET merge_status='merged', merged_into_supplier_id=:canonical_id
WHERE id IN (:dup_ids);

-- 4. 标记污染 Quote
UPDATE quotes SET bid_status='excluded_from_ref'
WHERE supplier_id IN (:inactive_ids);

-- 5. 守恒验证（SELECT，不产生写入）
-- 脚本在 COMMIT 前执行 Python 校验，不通过则 ROLLBACK

COMMIT;
```

### 7.5 正式生产执行

**前提**：`fix_package/` 已由负责人审核并签字（或代码审查批准）。

**步骤一：维护窗口 — 暂停写入**

通知用户维护窗口（建议低峰期，预留 30 分钟）。在生产服务器：
```
# 暂停应用的写入入口（前端 503 或停应用）
docker compose stop backend
```

**步骤二：再次备份生产库**
```
sqlite3 /opt/mempas/data/mempas.db \
  ".backup /opt/mempas/data/mempas-pre-cleanup-<exec-timestamp>.db"
sha256sum /opt/mempas/data/mempas-pre-cleanup-<exec-timestamp>.db
```
此备份作为最终回滚基准，与 Phase 1 的 `.bak` 文件区别保存。

**步骤三：校验生产当前状态与 `expected_before.json` 一致**
```
python scripts/verify_db_state.py \
  --db /opt/mempas/data/mempas.db \
  --expected data/production-cleanup-<ts>/fix_package/expected_before.json
```
任何字段不匹配（行数、金额）→ 中止，重新运行 §7.3 流程，不得强行继续。

**步骤四：单事务应用修复**
```
python scripts/apply_cleanup_to_copy.py \
  --db /opt/mempas/data/mempas.db \
  --package data/production-cleanup-<ts>/fix_package/ \
  --execute
```
脚本内部：
1. `BEGIN TRANSACTION`
2. 执行 `apply_cleanup.sql`（参数化，使用 `approved_merge_plan.json` 注入参数）
3. 运行守恒校验（Quote 行数、金额、project 关联、外键完整性）
4. 校验通过 → `COMMIT`；任何校验失败 → `ROLLBACK`，输出失败原因，退出非零状态

**步骤五：校验 `expected_after.json`**
```
python scripts/verify_db_state.py \
  --db /opt/mempas/data/mempas.db \
  --expected data/production-cleanup-<ts>/fix_package/expected_after.json
```
不一致 → 立即执行回滚（见下方）。

**步骤六：恢复应用并执行冒烟测试**
```
docker compose start backend
```
执行与 §7.3 步骤七相同的冒烟测试清单（供应商列表 / 历史报价 / 比价全流程 / 导出）。发现异常 → 执行回滚。

**回滚执行**（步骤四/五/六 任一失败时）：
```
# 方式 A：事务内已 ROLLBACK，数据库未变，直接重启应用
docker compose start backend

# 方式 B：数据库状态不确定时，从预执行备份恢复
docker compose stop backend
cp /opt/mempas/data/mempas-pre-cleanup-<exec-timestamp>.db \
   /opt/mempas/data/mempas.db
docker compose start backend
```

## 八、验收标准（11 条）

以下全部通过后方可关闭 Phase 2/3 迁移任务：

| # | 类型 | 验收内容 |
|---|------|---------|
| 1 | E2E | 上传并校对入库三份供应商报价 PDF（通过前端选择现有供应商）后，`suppliers` / `materials` / `quotes` 表行数完全不变；`bid_submissions` + `bid_quote_lines` 有对应新增记录 |
| 2 | E2E | 暂存报价（bid_status 任意值）不影响任何物料的 `ref_price_*` 字段，也不影响供应商推荐评分 |
| 3 | E2E | 不执行 `archive-prices`，也能完成对齐、复核、矩阵生成和 Excel 导出；导出结果与手工核对的 BidQuoteLine 数据一致 |
| 4 | E2E | 对同一报价事实，新路径（BidQuoteLine）和旧路径（历史 Quote）生成的矩阵中，对应行的单价、数量、金额结果一致 |
| 5 | E2E | 执行 `archive-prices` 后响应含 `eligible_count / archived_count / skipped_count / skipped_lines`；`material_id=NULL` 的行出现在 `skipped_lines` 中；`BidSubmission.status` 准确反映部分成功状态（`partially_archived`） |
| 6 | 单测 | `_resolve_supplier()` 对 `"凯硕新正投标文件.pdf"`（filename alias，去噪后精确匹配）和 `"凯硕新正（上海）机电设备科技发展有限公司"`（legal_name alias）均返回同一 `supplier_id` |
| 7 | 单测 | `_resolve_supplier()` 对全新未知名称返回 `{"error": "supplier_not_found"}`，`suppliers` 表行数不变 |
| 8 | 单测 | `tender_pdf.extract_bidlist()` 返回 `detected_category="阀门"`；前端 `tenderCategory` 值为 "阀门"，`material_class="水阀门"` 仅出现在 Step 2 UI 展示字段中，不影响任何查询或赋值 |
| 9 | 迁移校验 | Phase 1 完成后 `bid_alignment_items` 行数 = 迁移前行数；所有旧 `quote_id` 外键有效；CHECK 约束对全部旧行通过（旧行均为 `quote_id IS NOT NULL AND bid_quote_line_id IS NULL`） |
| 10 | 数据清洗 | `merge_suppliers.py --execute` 执行后，conservation_check 重新验证：每个合并簇的 Quote 行数、总金额、project_id 关联完全守恒；无 `quotes.supplier_id` 指向 `merge_status='merged'` 的供应商 |
| 11 | 数据清洗 | 清洗后 `refresh_material_baselines()` 重算完成，输出 `ref_price_changes.csv`；每条变动记录含变动前后值、样本数及排除原因；`needs_review=True`（变动幅度 > ±30%）的物料经人工确认后关闭 |
