# Material Master Data Standard Design

> **Status — audited 2026-06-23.** Largely matches the implementation in spirit, with field-name and structural divergences. The ORM model (`apps/api/models/material.py`) implements Layers 1–3, but several field names differ from this doc (e.g. `material_id` → `id` + `material_code`; the price-reference layer adds `ref_price_reasonable_low` and drops `deviation_threshold`'s sibling fields `recommended_brands`/`supplier_count` are present but `last_updated` is `updated_at`), and the extended-attribute schemas (`EXTENDED_ATTR_SCHEMAS` in `apps/api/core/config.py`) use a different key set and a `匹配`/`差异` role model not described here.
> _Originally written (date not recorded in source). English translation of the Chinese original; now the authoritative version._

> Reference: the SAP MM material master data system, simplified to fit the characteristics of the building electromechanical (M&E) installation industry.

## 1. Classification Hierarchy

```
Profession (8 professions; the last 4 pending customer confirmation)
├── Electrical (电气)          ← confirmed by customer
├── Plumbing & Drainage (给排水) ← confirmed by customer
├── HVAC (暖通)               ← confirmed by customer
├── Fire Protection (消防)     ← confirmed by customer
├── ? (pending)              ← possibly Intelligent Building / IT
├── ? (pending)              ← possibly Elevators
├── ? (pending)              ← possibly Curtain Wall
└── ? (pending)              ← possibly Other / Municipal / Steel Structure

Category (several categories per profession)
├── Electrical → cable tray, distribution box, cable, switch, luminaire ...
├── Plumbing & Drainage → pipe, valve, water pump, sanitary fixtures ...
├── HVAC → diffusers & dampers, A/C equipment, ductwork, insulation material ...
└── Fire Protection → alarm equipment, sprinkler, fire damper, extinguisher ...

Sub-category (subdivision under a category)
├── cable tray → tray type, ladder type, channel type
├── valve → butterfly valve, gate valve, check valve, ball valve
└── ...
```

Corresponding SAP hierarchy mapping: `Material Type (MTART) > Material Group (MATKL) > Specific Material (MATNR)`

## 2. Material Master Data Field Structure

### 2.1 Common Fields (shared by all categories)

| Field | Description | Source | Example |
|------|------|------|------|
| material_id | Material number, auto-generated by the system | System | MAT-EL-BRG-00001 |
| standard_name | Standard name (after standardization) | Standard template library | hot-dip galvanized tray cable tray |
| profession | Profession | Manual classification | Electrical |
| category | Category | Manual classification | cable tray |
| sub_category | Sub-category | Manual classification | tray type |
| spec | Spec / model | Extracted from quote | 300×150 |
| material_type | Material | Extracted from quote | hot-dip galvanized steel sheet |
| unit | Unit of measure | Standard template library | m |
| exec_standard | Execution standard | Quote / tech spec | JB/T 10216-2013 |

> (corrected 2026-06-23: the ORM model `Material` does not have a single `material_id` field. It uses an auto-increment integer `id` as the primary key plus a separate `material_code` string column for the human-readable code shown in the example. The model also carries a `brand` and a `status` column not listed here.)

### 2.2 Procurement Reference Information (auto-computed by the system from historical data)

| Field | Description | Computation |
|------|------|---------|
| ref_price_low | Reference price lower bound | Historical price P10 (10th percentile) |
| ref_price_avg | Reference average price | Mean of historical prices |
| ref_price_median | Reference median price | Median of historical prices |
| ref_price_high | Reference price upper bound | Historical price P90 (90th percentile) |
| price_cv | Price coefficient of variation | Standard deviation / mean |
| deviation_threshold | Deviation tolerance (%) | Auto-set based on CV; can be manually overridden |
| recommended_brands | Recommended brand list | Statistics over historically awarded brands |
| supplier_count | Number of historical suppliers | Deduplicated count |
| last_updated | Last update time | System automatic |

> (corrected 2026-06-23: the model adds a `ref_price_reasonable_low` field — described in code as the IQR-filtered minimum, i.e. the "reasonable historical low" — which is the value actually consumed by `scoring.py` as the price-competitiveness baseline. The `last_updated` field is named `updated_at` in the model.)

### 2.3 Extended Attributes (vary by category)

Extended attributes are defined as a JSON Schema; different categories mount different attribute sets.

**Cable tray:**

| Field | Description | Example |
|------|------|------|
| side_plate_thickness | Side-plate thickness (mm) | 1.2 |
| bottom_plate_thickness | Bottom-plate / cross-rung thickness (mm) | 1.2 |
| cover_plate_thickness | Cover-plate thickness (mm) | 1.0 |
| fire_rated | Whether fire-rated | true/false |

**Valve:**

| Field | Description | Example |
|------|------|------|
| nominal_diameter | Nominal diameter | DN100 |
| nominal_pressure | Nominal pressure | PN16 |
| connection_type | Connection type | flange / wafer / threaded |
| valve_type | Valve type | butterfly / gate / check |

**Diffusers & dampers:**

| Field | Description | Example |
|------|------|------|
| plate_thickness | Steel-sheet thickness (mm) | 1.2 |
| fire_rating | Fire rating | 70°C / 280°C |
| has_feedback | Whether it carries a feedback signal | true/false |

> (corrected 2026-06-23: these illustrative attribute keys do **not** match the implemented `EXTENDED_ATTR_SCHEMAS` in `apps/api/core/config.py`. The implementation keys schemas by category name and uses a different attribute key set, each entry carrying `key`, `label`, `source`, and a `role` of either `匹配` (match) or `差异` (difference) — e.g. for `阀门` the keys are `valve_type` / `pressure` / `body_material` / `connection`, not `nominal_diameter` / `nominal_pressure` / `connection_type` / `valve_type`. The doc's tables predate that schema and should be read as the original design intent only.)

## 3. Material Coding Rule

The recommended coding scheme is `profession-abbr - category-abbr - sequence`:

```
Format: {PROF}-{CAT}-{SEQ}
Example: EL-BRG-00001  (Electrical - cable tray - 00001)
        WS-VLV-00032  (Plumbing & Drainage - valve - 00032)
        HV-FAV-00005  (HVAC - diffuser/damper - 00005)
```

Profession abbreviation table:

| Profession | Abbr |
|------|------|
| Electrical | EL |
| Plumbing & Drainage | WS |
| HVAC | HV |
| Fire Protection | FP |
| Intelligent Building | IT |
| Elevators | EV |
| Curtain Wall | CW |
| Other | OT |

## 4. Standardization Matching Rules

The system must recognize that different written forms point to the same material. Core rules:

| Scenario | Example | Standardized result |
|------|------|-----------|
| Spec synonyms | DN100 / 100mm / 4寸 (4 inch) / Φ108 | DN100 |
| Name synonyms | 热浸镀锌 / 热镀锌 / 热浸锌 (variants of "hot-dip galvanized") | 热浸镀锌 (hot-dip galvanized) |
| Category synonyms | 电缆桥架 / 线缆桥架 / 桥架 (variants of "cable tray") | 桥架 (cable tray) |
| Dimension format | 300*150 / 300×150 / 300x150 | 300×150 |
| Type synonyms | 托盘式 / 槽式托盘 / 托盘型 (variants of "tray type") | 托盘式 (tray type) |

Standardization matching priority: exact match > rule match > AI semantic match > manual confirmation.
